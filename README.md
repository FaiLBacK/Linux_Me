# backupd — демон регулярного резервного копирования

Фоновый процесс для Linux: по расписанию копирует исходный каталог в каталог
резервных копий, добавляя в имя временную метку, пишет в системный журнал,
запускается вместе с системой (systemd) и управляется командой `backupctl`.
Python 3.8+, только стандартная библиотека.

## Состав

| Файл | Назначение |
|---|---|
| `backupd.py` | сам демон |
| `backupctl.py` | управление и мониторинг |
| `backupd.conf` | пример конфигурации |
| `backupd.service` | unit-файл systemd |
| `install.sh` | установка и удаление |
| `test_backupd.py` | автотесты |

## Установка

```sh
sudo ./install.sh            # копирует файлы, создаёт каталоги, включает автозапуск
sudo nano /etc/backupd/backupd.conf   # укажите source и destination
sudo backupctl reload        # применить без перезапуска
backupctl status
```

Что делает установщик: файлы в `/opt/backupd`, команды `backupd` и `backupctl`
в `/usr/local`, конфиг `/etc/backupd/backupd.conf` (права `600`, владелец root),
каталог копий с правами `700`, unit в `/etc/systemd/system`, затем
`systemctl enable --now backupd`. Путь `destination` из конфига
автоматически подставляется в `ReadWritePaths` unit-файла.
Удаление: `sudo ./install.sh uninstall` (конфиг и копии остаются).

## Конфигурация

Формат INI, файл `/etc/backupd/backupd.conf`. Изменения подхватываются по
`backupctl reload`; при ошибке в новом файле демон остаётся на прежних настройках
и пишет причину в журнал.

### Секция `[backup]`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `source` | обязателен | абсолютный путь к копируемому каталогу |
| `destination` | обязателен | абсолютный путь к каталогу копий (создаётся с правами 0700) |
| `interval` | обязателен | период: секунды или `30m`, `6h`, `1d`, `2w`; минимум 10 с |
| `mode` | `archive` | `archive` — один файл `.tar.gz`; `copy` — копия дерева каталогом |
| `prefix` | `backup` | начало имени копии |
| `keep` | `7` | сколько последних копий хранить (`0` — не удалять) |
| `exclude` | пусто | маски через запятую (`*.tmp, .cache`) |
| `verify` | `yes` | проверять архив после создания |
| `compresslevel` | `6` | сжатие gzip 1–9 |

### Секция `[daemon]`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `pidfile` | `/run/backupd/backupd.pid` | pid-файл с блокировкой (второй экземпляр не стартует) |
| `statusfile` | `/var/lib/backupd/status.json` | статус для мониторинга |
| `nice` | `10` | приоритет процесса (0–19) |
| `log_level` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` |

`pidfile`, `statusfile` и `nice` меняются только с перезапуском.

## Как проходит резервное копирование

1. Копия пишется во временный файл `.tmp-*` в каталоге назначения (права 0600).
2. Архив проверяется (читается целиком, сверяются CRC и число записей).
3. Файл атомарно переименовывается в `backup_ГГГГММДД_ЧЧММСС.tar.gz`
   (в режиме `copy` — каталог `backup_ГГГГММДД_ЧЧММСС`). Незавершённая копия
   никогда не появится под «настоящим» именем.
4. Удаляются самые старые копии сверх `keep`. Затрагиваются только файлы
   с именем вида `<prefix>_ГГГГММДД_ЧЧММСС[.tar.gz]`, чужие файлы не трогаются.

Особенности: символические ссылки сохраняются как ссылки (по ним нет перехода);
если `destination` лежит внутри `source`, он исключается из копии; файл, который
не удалось прочитать, пропускается с предупреждением (статус `warning`), а не
срывает всю копию. При ошибке следующая попытка через `min(interval, 5 мин)`.
После перезапуска расписание продолжается от последней успешной копии.

## Управление

```sh
backupctl status             # состояние демона и последней копии
backupctl backup-now --wait  # копия прямо сейчас (SIGUSR1) и ожидание результата
backupctl reload             # перечитать конфиг (SIGHUP)
backupctl set interval 2h    # изменить параметр (проверяется и применяется сразу)
backupctl set backup.keep 14
backupctl config             # действующая конфигурация
backupctl list               # имеющиеся копии
backupctl logs -n 100        # журнал
backupctl start | stop | restart | enable | disable   # через systemctl
```

`backupctl set` правит файл, сохраняя комментарии; новое значение сначала
проверяется во временном файле, и испорченный конфиг записан не будет.
Без systemd: `backupd -c /путь/к/конфигу` (демонизируется двойным fork),
`backupd --once` — одна копия и выход, `backupd --check-config` — проверка конфига.

Сигналы процессу: `SIGTERM`/`SIGINT` — остановка (текущая копия прерывается,
временные файлы удаляются), `SIGHUP` — перечитать конфиг, `SIGUSR1` — копия сейчас.

## Журнал и мониторинг

Сообщения уходят в syslog (facility `daemon`, тег `backupd`):

```sh
journalctl -t backupd -f
grep backupd /var/log/syslog        # если нет journald
```

Статус — файл `/var/lib/backupd/status.json` (время последней и следующей копии,
размер, число файлов, счётчики успехов и ошибок). Для систем мониторинга есть
`backupctl check` — одна строка и код возврата в стиле Nagios:

| Код | Когда |
|---|---|
| 0 OK | демон работает, последняя копия свежая |
| 1 WARNING | копия просрочена, есть предупреждения или копий ещё нет |
| 2 CRITICAL | демон не запущен, последняя попытка неудачна, копий нет дольше `interval` или последней более `2×interval` назад |
| 3 UNKNOWN | нет статуса или конфиг не читается |

Пример для cron/Zabbix/NRPE: `backupctl check`. В выводе есть perfdata
(`ok`, `failed`, `age`, `size`).

## Восстановление

```sh
tar -tzf /var/backups/backupd/backup_20261004_120000.tar.gz | head   # посмотреть состав
sudo tar -xzpf /var/backups/backupd/backup_20261004_120000.tar.gz -C /restore/  # распаковать
```

В архиве верхний каталог — имя исходного каталога (например `data/...`). Владельцы
и права сохраняются при распаковке от root (`-p`).

## Безопасность

- Конфиг: `root:root`, `600`. Демон отказывается стартовать, если файл доступен
  на запись всем или принадлежит постороннему.
- Каталог копий — `700`, файлы копий — `600` (`umask 077`, временные файлы
  создаются через `mkstemp`). При доступе посторонних демон пишет предупреждение.
- Unit-файл ограничивает процесс: `NoNewPrivileges`, единственная возможность
  `CAP_DAC_READ_SEARCH` (чтение любых файлов), файловая система только для чтения
  (`ProtectSystem=strict`, `ProtectHome=read-only`), запись лишь в каталог копий,
  из сетевых сокетов — только `AF_UNIX` (для syslog), `PrivateTmp`, защита ядра.
- Для источника, доступного обычному пользователю, лучше запускать демон не от
  root: добавьте в unit `User=backup`, а владельцем каталога копий сделайте этого пользователя.
- Файл статуса читаем всем (`644`), в нём нет секретов, только пути и счётчики;
  если пути тоже конфиденциальны, поставьте `chmod 640` и группу для мониторинга.
- Шифрования копий нет. Если каталог содержит секреты, храните `destination`
  на зашифрованном разделе или шифруйте копии внешним инструментом (`age`, `gpg`).

## Нагрузка на систему

`nice 10` + `IOSchedulingClass=idle` и `CPUSchedulingPolicy=idle` в unit-файле:
копирование выполняется, только когда диск и процессор свободны. Файлы
записываются потоково, память почти не растёт. Между копиями процесс спит
на событии и не потребляет CPU. Если сжатие нагружает процессор, уменьшите
`compresslevel` (1–3) или используйте `mode = copy`.
Если `destination` изменился, обновите `ReadWritePaths` в unit-файле
(`backupctl set destination` напомнит об этом).

## Тестирование

```sh
python3 -m unittest -v test_backupd
```

Тесты проверяют: разбор интервалов и валидацию конфигурации; архивы и копии,
исключения, симлинки, права файлов; ротацию (чужие файлы не удаляются);
прерывание без мусора; безопасное изменение конфига; жизненный цикл настоящего
процесса (первая копия по расписанию, `SIGUSR1`, `SIGHUP` с хорошим и битым
конфигом, защита от второго экземпляра, остановка по `SIGTERM`, удаление pid-файла).

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| Не стартует | `backupd --check-config -c /etc/backupd/backupd.conf`, `journalctl -u backupd` |
| `Read-only file system` в журнале | `destination` не совпадает с `ReadWritePaths` в unit-файле |
| «уже запущен» | работает другой экземпляр: `backupctl status` |
| `Permission denied` при `backup-now` | команда отправляет сигнал, запускайте от root (`sudo`) |
| В журнале «пропущен файл» | нет прав на чтение или файл исчез во время копирования |

## Ограничения

Копирование полное (не инкрементальное), каждый раз новый архив. Для больших
каталогов с редкими изменениями лучше `rsnapshot`/`restic`/`borg`. Файлы,
изменяющиеся во время копирования (например, базы данных), могут попасть
в копию в несогласованном состоянии: перед копированием сделайте дамп.
